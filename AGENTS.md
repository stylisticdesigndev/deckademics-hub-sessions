# Architecture rules
- Store Music Production enrollments, curriculum, and module completion separately from DJ records so production levels never trigger DJ certificates or alter DJ assessment rules.
- Keep instructor DJ and Production dashboards and curricula on separate routes, independent of the student/admin program switch; database policies remain responsible for authorizing production changes.
- Store teaching-program assignments separately in admin-managed instructor_programs; ProtectedRoute resolves those assignments before rendering instructor pages so login and deep links use the correct program.
- Store flexible Production lessons as ordered typed JSON blocks; render Markdown without raw HTML and use private signed media URLs to prevent executable lesson content and public file exposure.
- Keep Production lesson editing in a document-style canvas with shared inline block menus; preserve the existing block schema so presentation changes never alter student submissions or permissions.
- Keep Production submissions, intake, catch-up packets, and session packages in enrollment-scoped tables; students submit pending work, staff verify it, and only admins create/link program enrollment.
- Derive Production session balances from purchased credits and unique present attendance dates from the first package start; absence never consumes a session, and renewals append credits rather than erase history.
- Keep Production student routes enrollment-gated in a separate route module; existing shared student pages remain compatible with dual enrollment.
- Isolate the temporary Production showcase under its own provider and routes with browser-only sample records/files; reuse real lesson and learning screens, but never synthesize authentication or send showcase changes to Supabase.
- Share Production playback and submission review presentation between instructor, student, and showcase screens; derive bounce numbering from existing submissions and focused lesson selection from URL parameters so UI changes need no schema or permission changes.
- Adapt browser-only showcase messages to the existing DJ conversation list and role-specific threads; disable live attachment uploads in the showcase so shared presentation never writes sample data to school storage.
- Keep showcase profile edits and resized photo data in the showcase provider with defaults for older saved samples; never mount live account/security controls in sample profiles because they would change real accounts.
